# Rhythm 核心链路复盘与调整建议

> 日期：2026-10-13
> 依据：`2026-07-15-rhythm-product-discovery-handoff.md`、`2026-07-24-rhythm-product-delivery-todo.md`、当前代码实现
> 配套原型：`prototypes/ios-today-core.html`（今天页核心链路版）

## 1. 根本需求

> 帮助我通过持续实践理解自己，并逐渐找到真正适合自己的方法。

一个月后要得到的是：

1. 更清楚自己为什么会反复陷入某些状态；
2. 找到一两个真实验证过、适合自己的方法；
3. 阅读笔记真正影响生活。

"完成了多少任务"不是目标。所以产品里每个功能，都要能说清它在帮用户**收集证据、看见规律、验证方法**中的哪一步。

## 2. 核心链路

```text
每天（几秒）                         每几天（一分钟）            每轮结束（几分钟）
──────────────                       ────────────────            ──────────────
早上：定今晚一件事 + 娱乐结束时间
晚上：今晚做到了吗？完成/一点/没开始    检查点：先摆事实            轮次复盘：有效 / 调整再试 / 放下
随时：记一句（不分类）                 再只问一个问题                    │
      │                                                                ▼
      └──→ 系统建议归到某个议题（用户点 是/不是）              有效 → 我的方法（带适用条件和证据）
                 │                                                     调整 → 新一轮（必须写明改了什么）
                 └──→ 这周发现：带依据和样本量的规律 ──→ 下一轮试试
```

整条链路里，用户每天只做两件事：**晚上点一下结果**、**想到就记一句**。其余环节由系统汇总事实，用户只做确认。

## 3. 当前实现的断点

| 链路环节 | 现状 | 问题 |
|---|---|---|
| 早上定今晚安排 | `daily_arrangements` 的表、API 和 store 都有，但 `arrangements-band.tsx` 没被任何页面引用 | UI 上进不去；安排和实践也没有关联 |
| 晚上记录结果 | `PracticeLogInline` 的三态记录可用 | 这一步是好的 |
| 随手记 | `daily_captures` 只在今天页写入，只查当天 | 第二天就看不到了，也不关联议题或实践，**证据直接丢掉** |
| 看见规律 | `weekly_reviews`、`ai_recommendations` 只有读取接口，没有生成逻辑；`TrendsPane` 的完成率是写死的 | 「回顾」会一直是空的，链路第二步断了 |
| 检查点 | 没有 | 需求里的"每 3 天一个检查点"完全缺失 |
| 轮次 | 「调整再试」一点就开新一轮；轮次到期不会自动结束 | 出现 12 个空轮次；"一轮只改一个变量"没有体现 |
| 我的方法 | 复盘后没有"沉淀为方法"的入口；手动建方法时不写 `source_round_id` | **链路的终点断了**，方法和实践没有关系 |
| 议题 / 方向 | 议题页看不到关联的实践；方向是孤立表 | 议题只是一个名字列表 |
| 计划页 | 6 个等权的入口宫格 | 像配置后台，看不出先后关系 |
| 重复与遗留 | `PracticesList` 在计划和记录里各出现一次；"复盘"同时指每日复盘和轮次复盘；有十几个组件没被任何地方引用 | 增加理解成本 |

**结论**：现在只有"晚上记录结果"这一环是通的。记下来的东西没有流向任何地方，用户自然感觉不到"理解自己"。

## 4. 设计调整

### 4.1 今天页按"现在该做什么"组织，取消早上 / 中午 / 傍晚分组

按时段分组只是把记录换个顺序排，不帮用户做任何判断。需求里的"早、午、晚"只是**安排的时间属性**，不应该变成页面结构。

新顺序：标题行（右侧带本周记录小圆点）→ **今晚**（检查点作为记完后的追问放在同一张卡里）→ 这周发现 → 习惯 → 此刻。

控制密度的规则：

- 首屏只有一张主卡「今晚」；
- 本周记录不再单独占一张卡，收进标题行；
- 反思类内容（检查点、这周发现）同一时间最多出现一张，检查点优先。

### 4.2 安排和实践合并成一张「今晚」卡

在真实场景里，"早上定晚上做什么"本身就是实践的行动方案：实践轮次定义"每天要做的事"，安排是这件事在当天的具体时间，打卡是安排的结果。三者合成一张卡，随时间切换状态：

| 状态 | 卡片内容 |
|---|---|
| 早上（未定） | 「今晚安排什么？」默认带出本轮的行动方案（读 15 分钟、游戏玩到 21:30），点一下就定下来 |
| 晚上 | 大字显示「21:30 游戏结束，然后读 15 分钟」，下面是三态记录 |
| 记完后 | 显示结果和本轮进度条，可以改，「详细说说」是可选项 |

这样今天页就不再有"安排""实践""打卡"三个互相割裂的模块。

### 4.3 随手记从"当天消耗品"变成证据

- 记的时候不要求分类，这一点保留。
- 记完后，系统轻量建议「像是在说『下班后总被游戏带走』」，用户点「是 / 不是」。
- 确认后的记录进入议题证据，并被检查点和「这周发现」引用。
- 没归类的记录在记录页可以集中查看和整理，不再过了当天就消失。

### 4.4 检查点：先摆事实，只问一个问题

每 3 天出现一次：「4 天里开始了 3 次。没开始那天你记了『太累了』。累的时候，15 分钟是不是还太长？」可以一句话或语音回答，也可以跳过。这是把每天的记录转成理解的关键一步，成本控制在 30 秒内。

### 4.5 「这周发现」必须带依据，不能直接变成方法

需求第 9 节要求观察展示依据、样本量和不确定性。所以：

- 卡片上显示「依据 3 条记录，样本还少，可能只是巧合」；
- 按钮改为「下一轮试试 / 看依据 / 不太对」；
- 去掉之前原型里的「记成我的方法」：方法只能来自轮次复盘中用户确认有效的结论。

### 4.6 「连续记录」改成「本周有 N 天留下了记录」

保留原来的视觉，但文案从"连续"改为"本周 N 天"。断一天不归零，避免需求 5.2 里明确反对的记录压力。

### 4.7 新一轮必须写明改了什么

点「调整再试」时，要求填一句"这一轮改变什么"（只改一个主要变量）。本轮没有任何记录时，不允许直接开新一轮，只能延长或结束。这能从根本上避免出现空轮次。

### 4.8 方法是终点，要能被看见

轮次复盘选「有效」后，自动生成方法草稿：标题、适用条件、来源轮次和证据，由用户修改后确认。计划页把「我的方法」作为成果展示，而不是 6 个入口之一。

## 5. 与原需求冲突、需要确认的点

1. **全局「+」按钮**：需求第 12 节明确不接受全局悬浮加号。新原型已经去掉，记录入口放回今天页的「此刻」区。
2. **「我的」移到右上角头像，底部导航从 5 个变成 4 个**：需求第 10 节定的是 5 个入口。iOS 系统 App 普遍这样做，但需要你确认。
3. **自言自语（对话式记录）**：对应需求第 9 节的「深入聊聊」模式，作为后续功能保留。

## 6. 其他页面方向

- **计划**：按议题组织，每个议题下面是它的实践轮次和得出的方法；长期方向可选，放在顶部；习惯放在底部。取消 6 宫格。
- **记录**：负责证据和回顾，包括记录日历、实践轮次对比、全部随手记（可以筛选"未归类"）、周回顾和睡眠。只保留一份实践列表。
- **阅读**：划线上加「想试试」按钮，先选关联哪个议题，再成为该议题的候选解法。

## 7. 落地顺序

| 优先级 | 内容 |
|---|---|
| P0 | 今天页：做出「今晚」卡（接通 arrangements 和实践），「此刻」区展示全部随手记并支持关联，取消时段分组，换成新视觉 |
| P1 | 数据：arrangement 关联 `round_id`，新增随手记与议题/实践的关联表，新增检查点表，建方法时写入 `source_round_id` |
| P1 | 检查点；轮次复盘生成方法草稿；新一轮必须填改变的变量 |
| P2 | 「这周发现」先做规则版：完成状态 × 随手记关键词 × 时间做简单统计，之后再接 AI |
| P2 | 清理孤立组件和重复入口，统一"复盘"的叫法 |
