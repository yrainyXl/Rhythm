## 1. 文档目的

这份文档不是页面清单，而是 Rhythm 从“已有页面和数据接口”走到“可以真实长期使用”的交付清单。

产品完成的判断标准是：

1. 用户可以完成真实操作，数据能够保存、重载和继续使用；
2. 今天、计划、记录、阅读之间能够形成数据关联，而不是独立模块；
3. 一轮实践可以从问题出发，经历记录、检查点、调整和复盘，最终形成个人方法；
4. AI 的观察有证据、样本量和不确定性，用户拥有最终确认权；
5. iOS 主屏 PWA 在登录、挂起、恢复和弱网场景下保持可用；
6. 安全、权限、错误处理、测试和部署达到可上线标准。

### 优先级

- `P0`：发布阻断项，不完成不能上线。
- `P1`：核心产品闭环，不完成不能称为可用产品。
- `P2`：重要能力，完成后产品价值才完整。
- `P3`：后续增强，不阻断当前核心版本。

### 状态说明

- `[ ]`：尚未完成或尚未通过真实验收。
- `[x]`：已在当前分支实现，并有对应验证证据。
- 当前已有代码但缺少端到端验收的能力，仍按 `[ ]` 处理。

## 10. 核心产品闭环

### 10.1 闭环 A：从真实瞬间到个人方法

目标链路：

```text
留下真实瞬间
  -> 关联或建立议题
  -> 提出候选解法
  -> 发起第 1 轮实践
  -> 日常轻量记录
  -> 第 3 天检查点
  -> 结束并判断“调整再试”
  -> 发起第 2 轮实践
  -> 完整复盘
  -> 确认个人方法
```

验证清单：

- [ ] `LOOP-A-01` 瞬间可以不分类保存，之后再关联。
- [ ] `LOOP-A-02` 议题详情能看到原始瞬间，而不是只看到 AI 摘要。
- [ ] `LOOP-A-03` 实践与议题、来源和轮次关系完整保存。
- [ ] `LOOP-A-04` 普通日可以只做三态记录，不被强迫填写长表单。
- [ ] `LOOP-A-05` 检查点自动使用前 3 天事实，并只追问一个问题。
- [ ] `LOOP-A-06` 第二轮保留第一轮证据，并明确改变了哪个变量。
- [ ] `LOOP-A-07` 方法包含结论、适用条件、来源轮次和支持证据。
- [ ] `LOOP-A-08` 从方法可以回溯到轮次、日志和最初议题。

### 10.2 闭环 B：从阅读笔记到实践

目标链路：

```text
同步或手动添加笔记
  -> 浏览原始划线
  -> 点击“想试试”
  -> 关联当前议题
  -> 明确可验证假设
  -> 发起实践轮次
  -> 记录与复盘
  -> 回写尝试结果
```

验证清单：

- [ ] `LOOP-B-01` 微信读书和纸质书笔记使用一致的后续操作。
- [ ] `LOOP-B-02` 不是所有笔记都被推荐为实践，用户可以只收藏或关联方向。
- [ ] `LOOP-B-03` 创建实践时显示原始观点和用户要解决的问题。
- [ ] `LOOP-B-04` 实践页可以回到来源笔记，笔记页可以查看实践结果。
- [ ] `LOOP-B-05` AI 推荐被拒绝后不持续重复出现。

### 10.3 闭环 C：从一周事实到下一步调整

目标链路：

```text
安排 + 实践日志 + 瞬间 + 每日复盘
  -> 自动汇总周事实
  -> 生成带证据的观察
  -> 用户确认或修正
  -> 调整下一轮实践或沉淀方法
```

验证清单：

- [ ] `LOOP-C-01` 周统计与原始记录复算一致。
- [ ] `LOOP-C-02` 观察明确区分“事实”“可能关系”“用户结论”。
- [ ] `LOOP-C-03` 用户修正后保存修正内容，不再展示旧结论。
- [ ] `LOOP-C-04` 从周回顾创建的下一步能出现在计划页和今天页。
- [ ] `LOOP-C-05` AI 不可用时仍能查看基础统计和原始记录。

## 11. 黄金路径端到端验收

使用真实场景：

> 18:30 下班，回家后想先吃饭和娱乐，但经常停不下来。希望早上提前决定晚上做一件有积累的事情，并验证怎样更容易开始。

### 第 1 天

- [ ] 早上创建“晚上 20:30 做个人项目 15 分钟”的安排。
- [ ] 建立议题“为什么下班回家后总会陷入游戏和手机？”
- [ ] 发起第 1 轮实践：“早上确定晚上最重要的一件事”，周期 6 天。
- [ ] 晚上用“没开始”完成轻量记录，并补充“吃饭后打开游戏就停不下来”。

### 第 2-3 天

- [ ] 每天只需三态记录即可完成，不强制详细复盘。
- [ ] 第 3 天出现检查点，自动汇总完成/部分/没开始次数。
- [ ] 检查点只追问一个问题，例如“没开始的日子，娱乐是否都没有结束时间？”

### 第一轮结束

- [ ] 展示真实日志、完成率、常见原因和用户原话。
- [ ] 用户选择“调整再试”，结论为“只有明确目标还不够”。
- [ ] 创建第 2 轮：“确定一件事，同时约定娱乐结束时间”。

### 第二轮结束

- [ ] 对比两轮的开始率、原因和用户结论。
- [ ] 用户确认方法：“工作日晚间行动需要明确目标、娱乐结束点和低启动成本。”
- [ ] 方法保存适用条件，并能回溯两轮实践和原始记录。

### 阅读补充路径

- [ ] 从《深度工作》的一条相关划线点击“想试试”。
- [ ] 关联同一议题，创建或补充下一轮假设。
- [ ] 实践结束后，划线详情显示尝试结果，而不是只显示“已收藏”。

整个黄金路径通过，才可以认为 Rhythm 的核心产品闭环成立。

## 13. 真实使用验证

功能闭环通过后，继续进行 30 天个人使用验证。成功标准不是完成任务数量，而是能否帮助用户理解自己并形成方法。

### 第 1 周：记录压力

- [ ] 每天是否可以在 3 秒左右完成轻量记录。
- [ ] 自由记录是否能先保存、后整理。
- [ ] 漏记一天后是否可以自然继续，而不会产生补录压力。

### 第 2 周：实践可执行性

- [ ] 是否真的使用了早上安排晚间行动的功能。
- [ ] 检查点问题是否减少重复填写，而不是增加负担。
- [ ] 是否能清楚说出这一轮只改变了什么。

### 第 3 周：调整能力

- [ ] 是否自然发起第二轮，而不是重新创建一个无关任务。
- [ ] 两轮差异和结果是否足够清楚。
- [ ] 系统观察是否提供了证据，而不是只给泛泛建议。

### 第 4 周：长期价值

- [ ] 是否形成至少一条愿意继续使用的个人方法。
- [ ] 是否有一条阅读笔记真正进入了实践。
- [ ] 是否比使用前更清楚自己为什么反复陷入某种状态。
- [ ] 是否愿意继续使用，而不是因为记录负担放弃。

30 天通过标准：

1. 至少一个议题完成两轮实践；

5. 用户主观认为记录负担可接受，并愿意继续使用。
